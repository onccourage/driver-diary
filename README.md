# Дневник смен водителя

Мини-проект: сервер (HTTP API) + консольный клиент. Python 3.9+, **без внешних зависимостей**.

## Запуск
```bash
python server.py            # сервер на :8000, данные в data/trips.json
python client.py            # консольный клиент (в другом терминале)
python -m unittest discover -s tests -v   # тесты
```
Клиент: `n` — следующий день, `p` — предыдущий, `d 2026-10-01` — выбрать дату, `a` — добавить поездку, `q` — выход.
В примере данных поездки за **2026-10-01**.

## API
- `GET /api/trips?date=YYYY-MM-DD` → `{date, summary, trips}`
  summary: `trips`, `revenue`, `commission`, `on_hand`, `cash{trips,amount}`, `card{trips,amount}`
- `POST /api/trips` → `201` создана, `200` дубль (ничего не создано), `422` ошибка данных,
  `409` тот же `id`, но другие данные, `400` невалидный JSON.

## Решения и допущения
- «На руки» = выручка − комиссия (наличные/карта показаны отдельно).
- День поездки — по дате начала в часовом поясе самой поездки.
- Валидация: `amount > 0`, `end > start`, часовой пояс обязателен, `payment ∈ {cash, card}`, `0 ≤ commission ≤ amount`.
- Защита от дублей: по `id`; если `id` не передан — генерируется из содержимого (повтор даст тот же id);
  то же содержимое под другим `id` тоже считается дублем.
- Хранилище — JSON-файл, запись под блокировкой.

## Как использовал ИИ
Я использовал Claude для написания проекта целиком по тексту задания: разбил работу на слой логики (service.py), HTTP-сервер, консольный клиент и тесты. Выбрал стек без внешних зависимостей (стандартная библиотека Python), чтобы проект запускался одной командой.

Где ИИ ошибся или был неточен:

Тест на конфликт дублей. ИИ написал тест, где поездка с тем же id, но другой суммой должна давать 409. Тест падал с 422: он подставил сумму 5, а комиссия в данных 360, и валидация (комиссия не больше суммы) срабатывала раньше. Ошибка была в тесте, а не в коде. Я заменил сумму на 9999.
Неоднозначность «на руки». В задании не сказано, как считать эту величину. ИИ выбрал «выручка минус комиссия» и зафиксировал это допущение в README. Я проверил, что такая трактовка подходит, наличные и карта при этом показаны отдельно.

Что я проверил и поправил сам:

Запустил тесты и клиент вручную на примере данных из задания, сверил цифры сводки (3900 выручка, 585 комиссия, 3315 на руки).
Продумал защиту от дублей: по id, а если id нет, то по содержимому поездки. Повтор возвращает 200 и не создаёт запись.
